# PROJECT.md

## 1. Что такое 1С Аналитик

`1C_Analitik` - Windows-приложение для аналитика 1С на живом созвоне. Оно захватывает микрофон и loopback, локально распознаёт русскую речь, ведёт стенограмму, выбирает профильные skills, формирует AI-подсказки и автоматически сохраняет результаты встречи.

## 2. Продуктовый принцип UX v3 - Analyst Cockpit

Пользователь управляет **встречей и задачей**, а приложение само управляет техническим контуром. Интерфейс должен показывать только то, что полезно на текущем этапе встречи.

Три пользовательских состояния:

1. **До встречи** - тема, readiness микрофона/собеседника/STT/ИИ, последние встречи и одна основная кнопка запуска.
2. **Во время встречи** - стенограмма слева, рабочая подсказка 1С Аналитика справа, таймер, состояние звука, новая тема и завершение.
3. **После встречи** - метрики встречи, локальный протокол и вкладки итогов, решений, задач, вопросов и стенограммы.

В основном интерфейсе остаются только необходимые действия:
- начать / завершить встречу;
- спросить 1С Аналитика;
- начать новую тему;
- переключить полный / компактный режим;
- очистить текущую стенограмму и подсказку;
- открыть настройки при необходимости.

Устройства, STT, сохранение, протокол, skill routing и проверка обновлений должны по возможности работать автоматически и не требовать постоянного ручного управления.

Компактный режим около 440 px предназначен для размещения 1С Аналитика рядом с окном 1С или программой созвона. В live-сценарии он приоритизирует подсказку и временно скрывает полную стенограмму без удаления данных.

## 3. Основной поток

`microphone + loopback -> local STT -> transcript/context -> skill selection -> GPT-5.6 Sol -> live hint`

Если во время генерации подсказки приходят новые человеческие реплики, они не считаются автоматически отвеченными старой подсказкой. После завершения текущего ответа приложение ставит последнюю новую реплику в catch-up очередь и запускает следующий анализ без повторного полного debounce. Для catch-up фиксируется граница стенограммы на момент запуска предыдущего запроса: реплики до этой границы остаются только контекстом, а текущим запросом считаются только человеческие реплики, появившиеся после неё. Уже обработанный вопрос не должен повторно получать полный разбор, если новые реплики прямо этого не требуют.

После завершения:

`transcript -> local archive -> local 1C protocol -> decisions/actions/questions -> summary workspace`

Контур поставки:

`source -> tests -> PyInstaller -> Inno Setup -> installed UI self-test -> GitHub Release`

## 5. Автономность

Без сети должны продолжать работать:
- захват аудио;
- STT;
- стенограмма;
- локальное сохранение;
- локальный протокол;
- итоговый экран встречи на основе локального протокола.

Сеть используется только для функций, которым она действительно нужна:
- GPT-подсказки;
- проверка и скачивание обновлений.

Проблема сети не должна останавливать саму встречу.

## 6. UI и количество действий

Presentation-layer находится в `meeting_bridge/gui_runtime.py` и не должен менять архитектурные границы capture/STT/context/skills/LLM.

Технические функции не выводятся отдельными кнопками в основной сценарий, если их можно выполнить автоматически.

Не должны быть постоянными главными действиями:
- отдельные Start и Stop;
- «Сохранить настройки»;
- «Модель STT» при исправном bundled-компоненте;
- «Сохранить диалог»;
- «Сделать протокол»;
- отдельный режим «Вслух»;
- «В диалог» и «В диалог + Ответ ИИ»;
- отдельная кнопка вставки из буфера.

Live workspace должен сохранять правило:
- человеческий разговор отображается в стенограмме;
- AI-ответ не дублируется в стенограмме и отображается в отдельной панели подсказки;
- «Что сказать сейчас» визуально важнее подробного разбора;
- технический статус показывается только в понятных пользовательских формулировках.

Кнопка «Очистить» является пользовательским действием текущей сессии: она очищает текущую live-стенограмму, текущую AI-подсказку и текущий AI-контекст, но не удаляет ранее сохранённые архивы и протоколы.

Эти возможности либо автоматизированы, либо доступны в контекстном/аварийном сценарии.

## 7. Профессиональные правила 1С

- Факты, выводы и гипотезы не смешивать.
- БУ, НУ и НДС анализировать раздельно, если нет основания объединять.
- Не придумывать документы, регистры, реквизиты, проводки и настройки.
- При недостатке evidence указывать, что именно проверить в 1С.
- Перед объяснением остатка или сальдо как нормального сначала проверять природу бухгалтерского счёта/объекта: может ли он иметь конечное сальдо после закрытия, на каком объекте экономически должно оставаться НЗП и не перепутан ли БУ-счёт с управленческим регистром или другой аналитикой ERP. Для счёта 25 конечный остаток после закрытия нельзя автоматически объяснять нормальным НЗП без проверки стандартной/нетиповой методологии и фактического объекта учёта.
- Проверочные изменения, перерасчёты и смену настроек для проверки гипотез выполнять только в копии базы, тестовом контуре или другом изолированном стенде. В рабочей базе не рекомендовать «изменить и посмотреть», «перепровести на пробу» или «вернуть изменение обратно»; PROD исправлять только после доказательства причины и определения конкретного первоисточника.
- Новая человеческая реплика, появившаяся во время in-flight AI-ответа, не считается отвеченной этим ответом. После завершения текущего запроса её нужно поставить в catch-up очередь и обработать отдельным следующим запросом.
- В catch-up запросе уже обработанная реплика остаётся только контекстом. Текущий запрос начинается строго после сохранённой границы стенограммы и включает все новые человеческие реплики после неё, даже если между ними разные роли «Я» и «Собеседник».
- Skill routing использует только текущую тему и очищенный человеческий контекст.
- Предыдущие ответы ИИ не должны становиться доказательством для следующего ответа.

## 8. Безопасность и данные

Локальными считаются:
- `config.yaml`;
- код доступа/API key;
- `live-transcript.md`;
- `transcripts/`;
- `*.log`;
- модели и локальные рабочие файлы.

Запрещено:
- коммитить пользовательские ключи и стенограммы;
- встраивать реальный серверный API key в клиент или release asset;
- скрытно отправлять архив встреч во внешний сервис;
- ослаблять managed-access validation ради удобства UX.

## 9. Критерии качества

Для UX/автономности изменение считается готовым после:
1. unit/regression tests UX-логики;
2. regression tests существующего capture/STT/LLM/session контура;
3. успешной сборки PyInstaller;
4. успешной сборки Inno Setup;
5. installed `--self-test`;
6. создания реального cockpit UI в installed self-test без запуска audio-bootstrap;
7. проверки типового сценария: запуск -> встреча -> авто/ручная подсказка -> завершение -> автоматический протокол -> итоговый экран.

Успешная сборка сама по себе не является доказательством корректности профессиональных выводов 1С.
