# 1С Аналитик

**1С Аналитик** - Windows-помощник для аналитика 1С на живых встречах. Приложение слушает микрофон и звук собеседника, локально распознаёт русскую речь, ведёт стенограмму, автоматически подключает профильные 1С-skills и при необходимости даёт подсказки через GPT-5.6 Sol.

Последняя Windows-версия распространяется одним установщиком: `1C-Analitik-Setup.exe` из GitHub Releases.

## Для пользователя

После установки отдельные Python, Git, PowerShell, STT-модель и техническая настройка не нужны.

Первый запуск:
1. приложение просит персональный код доступа к 1С Аналитик;
2. автоматически ищет микрофон и звук собеседника;
3. проверяет локальное распознавание речи и доступ к ИИ;
4. показывает статус **«Готов к работе»**.

Дальше основной сценарий состоит из нескольких действий:
- **Начать встречу / Завершить встречу** - одна кнопка для управления записью;
- **Спросить ИИ** - ручной вопрос помощнику;
- **Новая тема** - отделить новый независимый вопрос от предыдущего AI-контекста;
- **Настройки** - нужны только если приложение не смогло автоматически подобрать аудиоустройства или требуется отключить автоподсказки.

Технические действия вроде отдельного сохранения настроек, скачивания STT-модели, ручного сохранения диалога и отдельной кнопки создания протокола из основного интерфейса убраны.

## Что происходит автоматически

При старте встречи приложение:
- выбирает сохранённые или наиболее подходящие аудиоустройства;
- сохраняет выбранные устройства без отдельной кнопки;
- запускает локальное распознавание речи;
- ведёт текущую стенограмму;
- отслеживает реплики и при включённых автоподсказках самостоятельно решает, когда запросить помощь ИИ;
- выбирает до трёх наиболее релевантных профессиональных skills;
- показывает последнюю подсказку отдельно от бегущей стенограммы.

После завершения встречи приложение автоматически:
- сохраняет копию стенограммы;
- формирует локальный 1С-ориентированный протокол;
- выделяет решения, поручения и открытые вопросы;
- показывает количество найденных решений, задач и вопросов;
- предлагает открыть готовый протокол.

Формирование локального протокола не требует OpenAI и работает без передачи стенограммы во внешний AI-сервис.

## Подсказка на созвоне

Обычный AI-ответ формируется в двух уровнях:

1. **Что сказать сейчас** - короткая формулировка на 2-4 предложения, которую можно использовать прямо на встрече.
2. **Разбор** - профессиональная диагностика, что проверить в 1С и какие уточнения нужны.

Если пользователь явно просит строгий формат, например одно слово, одну фразу или только «да/нет», этот формат имеет приоритет.

## Автоподсказки

По умолчанию свежая установка включает автоподсказки. После паузы в речи 1С Аналитик может самостоятельно подготовить ответ или пропустить реплику, если отвечать не требуется.

Защита от лишних вызовов уже встроена:
- один и тот же вопрос не обрабатывается повторно;
- ручной и автоматический запросы не запускаются параллельно на одну реплику;
- учитывается пауза после речи;
- модель может вернуть `SKIP`, если полезного ответа сейчас не требуется.

## Контекст и смена темы

Кнопка **«Новая тема»** создаёт границу AI-контекста, но не удаляет стенограмму встречи.

Дополнительно приложение консервативно отслеживает смену типа задачи. Если новая реплика заметно относится к другому классу 1С-задач, пользователь получает подсказку отделить новый контекст. Автоматическое разделение без подтверждения не выполняется, чтобы не потерять важную связь между вопросами.

## Профессиональные skills

В установщик входят 9 методик:
- `evidence-driven-diagnosis`;
- `accounting-bu-nu-vat`;
- `1c-requirements-analysis`;
- `1c-test-case`;
- `meeting-analyst`;
- `1c-data-consistency`;
- `1c-closing-month`;
- `1c-document-movements`;
- `1c-report-analysis`.

Skills выбираются автоматически по текущему вопросу и контексту текущей темы.

## Автономность

Часть функций полностью локальна:
- захват микрофона и loopback;
- русское STT на `sherpa-onnx`;
- стенограмма;
- локальное хранение встреч;
- формирование базового 1С-протокола.

Интернет нужен для:
- AI-подсказок GPT-5.6 Sol;
- проверки обновлений;
- скачивания обновления.

Если интернет или AI-сервис временно недоступны, запись встречи, распознавание речи, сохранение стенограммы и локальный протокол продолжают работать.

## Доступ к ИИ

Рекомендуемый режим - **managed access**. Пользователь вводит только персональный код `1CA-...`. Серверный OpenAI API key хранится на сервере и не попадает в установщик или на компьютер пользователя.

Архитектура:

`1С Аналитик на ПК -> защищённый gateway -> OpenAI`

Приложение также сохраняет совместимость с direct OpenAI-compatible режимом для разработки и специальных сценариев.

## Обновления

Установленная версия проверяет GitHub Releases в фоне после запуска. Проверка больше не блокирует открытие приложения.

Если новая версия доступна, в настройках появляется действие **«Обновить до ...»**. Обновление нельзя запускать во время активной встречи. Перед установкой скачанный EXE проверяется по SHA-256 digest из GitHub Release.

## Системные требования

- Windows 10/11 x64;
- микрофон;
- устройство воспроизведения, для которого Windows/PyAudioWPatch предоставляет `[Loopback]`;
- интернет только для AI-подсказок и обновлений.

## Данные пользователя

Локально и вне GitHub хранятся:
- `config.yaml`;
- персональный код доступа или пользовательский API key;
- `live-transcript.md`;
- `transcripts/`;
- диагностические `*.log`.

Стенограмма не должна скрытно отправляться в сторонние сервисы. Во внешний AI-сервис передаётся только контекст, необходимый для явной функции AI-подсказки.

## Для разработчика

Запуск из исходников:

```powershell
git clone https://github.com/Aleksey341/1C_Analitik.git
cd 1C_Analitik
powershell -ExecutionPolicy Bypass -File .\install.ps1
.\start.ps1
```

Тесты:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Основной UI находится в `meeting_bridge/gui_v2.py`. Старый `meeting_bridge/gui.py` сохранён как проверенное ядро поведения и набор совместимых методов захвата, стенограммы и AI orchestration.

## Сборка Windows

`.github/workflows/release-windows.yml`:
1. запускает тесты;
2. скачивает русскую STT-модель;
3. собирает приложение через PyInstaller;
4. собирает Windows installer через Inno Setup;
5. устанавливает пакет в временный каталог и выполняет `--self-test`;
6. публикует установщик в GitHub Release.
