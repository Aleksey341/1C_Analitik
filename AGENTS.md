# AGENTS.md

## Назначение
Единые правила AI-агентов для `1C_Analitik`. Проект следует AI Project Standard 1.0 из `Aleksey341/cursor-ai-workspace/_AI_WORKSPACE/AI-Project-Standard` и дополняет его правилами Meeting Bridge и предметной области 1С.

## Перед началом работы
- Прочитать `README.md`, `PROJECT.md`, релевантные docs, skills, тесты и существующую реализацию.
- Определить затронутый контур: audio capture, loopback, STT, контекст встречи, OpenAI, skills, UI, installer или release pipeline.
- Найти уже существующую реализацию до создания новой.
- Для нетривиального изменения определить критерий готовности: unit/regression test, smoke test, build или проверяемый пользовательский сценарий.

## Режимы работы
- `Review` - анализ без правок.
- `Direct` - небольшое очевидное изменение.
- `Investigation` - диагностика ошибки аудио, STT, LLM, skills или сборки.
- `TDD-first` - изменение контекстной логики, выбора skills, AI-response pipeline, storage или критичного поведения Meeting Bridge.

## Архитектурные границы
Основной поток:

`microphone + loopback -> local STT -> transcript/context -> skill selection -> OpenAI -> UI / protocol`

Отдельно:

`source -> PyInstaller -> Inno Setup -> GitHub Release`

Не смешивать без необходимости:
- захват аудио;
- распознавание;
- хранение стенограммы;
- выбор skills;
- AI orchestration;
- presentation/UI;
- installer/release.

## Предметные правила 1С
- Ответы и подсказки должны опираться на evidence из текущего вопроса, стенограммы и подключенных skills.
- БУ, НУ и НДС не смешивать без явного основания.
- При недостатке данных формулировать, что требуется проверить в 1С.
- Не придумывать документы, проводки, движения регистров или настройки конфигурации.
- Изменение профессиональной логики skills проверять отдельным сценарием.

## Безопасность
- Не коммитить `config.yaml`, API keys, локальные transcripts, logs и пользовательские материалы.
- Не добавлять реальные ключи в установщик, release assets или пример конфигурации.
- Не включать скрытый сетевой сбор содержимого встреч.
- Изменение хранения стенограмм или передачи текста во внешние сервисы требует явного описания в `PROJECT.md` и пользовательской документации.

## Проверка изменений
Перед завершением задачи:
1. запустить самый узкий релевантный тест;
2. затем связанные regression/smoke проверки;
3. для release-изменений проверить workflow и упаковку;
4. для AI/skill изменений проверить поведение на типовом и граничном кейсе;
5. не считать успешную сборку доказательством корректности предметной логики.

## Meeting Bridge - специальные заметки
Диалог и протоколы ведутся **в приложении Meeting Bridge**, не в чате Cursor.

Если пользователь просит разобрать запись:
1. смотреть файлы в `transcripts/` (`dialog-*.md`, `protocol-*.md`) или `live-transcript.md`;
2. не вызывать MCP `session_start` / `session_stop`, пока открыт GUI.
